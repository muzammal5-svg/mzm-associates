### RLS Helper Functions

**`is_super_admin()`** — Returns true if current user has role='super_admin'
```sql
SELECT EXISTS (
  SELECT 1 FROM public.profiles 
  WHERE id = auth.uid() AND role = 'super_admin'
)
```
**Security**: ✅ Correct — Uses auth.uid() (JWT claim) not user input

**`current_firm_id()`** — Returns firm_id from current user's profile
```sql
SELECT firm_id FROM public.profiles WHERE id = auth.uid()
```
**Security**: ✅ Correct — JWT-based, cached by Supabase

**`is_owner()`** — Returns true if current user is firm owner
```sql
SELECT is_owner FROM public.profiles WHERE id = auth.uid()
```
**Security**: ✅ Correct — Prevents privilege escalation

**`read_access(firm_uuid)`** — Grants read to active users in firm
```sql
firm_id = p_firm_id AND user_id IN (
  SELECT id FROM profiles WHERE firm_id=p_firm_id AND is_active=TRUE
)
```
**Security**: ✅ Correct — Checks is_active flag, prevents revoked user access

**`write_access(firm_uuid)`** — Grants write to admin/lawyer/super_admin
```sql
firm_id = p_firm_id AND user_id IN (
  SELECT id FROM profiles WHERE firm_id=p_firm_id AND role IN ('admin','lawyer') AND is_active=TRUE
)
```
**Security**: ✅ Correct — Role-based, checks is_active

## Authentication & Authorization

### Sign-Up Flow Security
```typescript
// web/app/register/page.tsx

1. User enters email/password/firm name/phone
2. supabase.auth.signUp({ email, password })
   → Supabase generates JWT, stores hashed password
3. register_firm(firmName, fullName, phone) RPC called
   → v_user := auth.uid() — Extract from JWT
   → Check profile doesn't exist (prevent duplicate)
   → Create firm row
   → Create profile row with is_owner=TRUE, role='admin'
   → Create trial subscription (7 days default)
   → Trigger createProfileCompleteTrigger (if exists)
4. Router redirects to /billing or /
```
**Security Assessment**:
- ✅ RPC enforces auth.uid() — No SQL injection
- ✅ Check profile existence prevents duplicate reg
- ✅ is_owner set atomically with profile creation
- ✅ Trial defaults to app_settings.trial_days (configurable)
- ⚠️ **Issue**: If signUp succeeds but signIn fails → profile orphaned (minor, cleanup via RPC or admin)

### Sign-In Flow Security
```typescript
// web/app/auth/sign-in/page.tsx

1. User enters email/password
2. supabase.auth.signInWithPassword({ email, password })
   → Supabase verifies password hash against stored hash
   → Returns JWT with auth.uid() claim
3. AuthProvider.onAuthStateChange fires
   → Fetch profile row WHERE id = auth.uid()
   → Verify profile.is_active=TRUE
   → Set profile state + firm state
4. useRequireAuth hook evaluates:
   → Check user exists
   → Check profile exists (redirect if missing)
   → Check allowedRoles (redirect if not matched)
   → Check subscription state (redirect if expired)
```
**Security Assessment**:
- ✅ Password hashing via Supabase auth
- ✅ JWT contains immutable auth.uid() claim
- ✅ is_active check prevents revoked user access
- ✅ Role-based routing enforced
- ✅ Subscription gating prevents access during grace/expired

### Session Management
```typescript
// AuthProvider: JWT token refresh

supabase.auth.onAuthStateChange((event, session) => {
  // AUTO REFRESH: Supabase client auto-refreshes before expiry
  // if refreshToken stored in localStorage
```

**Security Assessment**:

### Device Token Tracking

```typescript
// AuthProvider: register_device RPC on sign-in

saasRpc.registerDevice(deviceId, label, sessionId)
```

## Subscription Gating & Enforcement

### Subscription State Machine
```
trialing
├──→ (after 7 days) → grace
│   └──→ (after 3 days grace) → expired
└──→ (payment verified) → active
     ├──→ (after X months) → grace
     └──→ (after grace) → expired
     └──→ (admin action) → suspended
```

### Access Control Per State
```typescript
// useRequireAuth hook decision tree

if (status === 'active') → Grant access ✓
if (status === 'trialing') → Grant access ✓
if (status === 'grace') → Grant access + show warning banner ✓
if (status === 'expired' || 'suspended' || 'cancelled') → Redirect to /billing ✗
if (status === 'pending') → One-shot refresh, if still pending → redirect to /billing ⚠️
if (status === 'none') → Redirect to /billing (no subscription) ✗
```

### Seat Limit Enforcement
```sql
CREATE OR REPLACE FUNCTION public.seats_used(p_firm_id UUID)
RETURNS INT LANGUAGE sql STABLE SECURITY DEFINER AS $$
  SELECT COUNT(*)::INT FROM public.profiles 
  WHERE firm_id=p_firm_id AND is_active;
$$;

CREATE OR REPLACE FUNCTION public.seat_limit(p_firm_id UUID)
RETURNS INT LANGUAGE sql STABLE SECURITY DEFINER AS $$
  SELECT COALESCE(
    (SELECT p.max_users FROM public.subscriptions s 
     JOIN public.plans p ON p.id=s.plan_id 
     WHERE s.firm_id=p_firm_id 
     ORDER BY s.ends_at DESC LIMIT 1), 
    5  -- default limit
  );
$$;
```

**Security Assessment**: ✅ Strong — Queries are immutable functions, no injection possible
